# Requirements for Japanese Fonts / 日本語フォントの要件

## Introduction / はじめに

A Japanese font is not only a collection of glyph outlines. It also defines a coordinate system within which full-width ideographs, kana, punctuation, and glyphs from other scripts are placed. That coordinate system is needed to compose a Japanese line consistently, to place a line on a grid, to calculate leading, and to make text from several fonts and several point sizes sit together without appearing to drift.

日本語フォントは、単なる字形アウトラインの集合ではない。全角の漢字、かな、約物、さらに他の文字体系の字形をどの座標系に配置するかも定義する。この座標系がなければ、日本語の行を一貫して組むこと、行をグリッド上に配置すること、行送りを算出すること、複数のフォントや複数のポイントサイズを混在させても見かけ上の位置をずらさないことはできない。

### A hybrid coordinate system / 混成された座標系

A Japanese font that contains both Japanese and Latin glyphs combines two different writing-system models. Latin glyphs are normally proportional and are conventionally aligned through the Roman baseline. Japanese glyphs are most often full-width and are placed in a CJK em-box, usually by its center. Traditional Japanese typography has no corresponding Roman-baseline alignment model.

和文とラテン文字を併せ持つ日本語フォントは、異なる二つの書記体系のモデルを一つに収めている。ラテン字形は通常プロポーショナルであり、慣例上ローマンベースラインによってそろえられる。日本語字形の大部分は全角であり、CJK em-box の中に、通常はその中心を基準として置かれる。伝統的な日本語組版には、これに対応するローマンベースラインによる整列モデルはない。

Digital font coordinates nevertheless normally inherit the Latin convention: the font origin is placed on the Roman baseline. This makes separately designed Latin fonts automatically compatible at a shared baseline, but the origin is not a natural Japanese alignment point and its relationship to Japanese glyphs is not consistent from one Japanese font to another. A Japanese glyph can be drawn correctly within its em-box while that box sits above, below, or asymmetrically around the coordinate origin.

それにもかかわらず、デジタルフォントの座標は通常、ラテン文字由来の慣行を継承し、フォント原点をローマンベースライン上に置く。これにより、別々に設計されたラテンフォントは共通のベースラインで自動的に互換になる。しかし、その原点は日本語にとって自然な整列点ではなく、日本語字形との関係も日本語フォントごとに一定ではない。日本語字形自体が em-box 内に正しく描かれていても、その box は座標原点の上方、下方、または非対称な位置に存在し得る。

The design space of a Japanese digital font is therefore hybrid. It contains a usually one-em CJK rectangle that defines the Japanese cell, while its coordinate origin commonly serves Latin-baseline compatibility. A layout engine must resolve the conversion from that origin to the CJK em-box edges and center before it places Japanese glyphs on a line, aligns them with another Japanese font, or measures Japanese leading. Treating the Roman baseline origin as though it were the Japanese baseline gives different—and often incorrect—results for different fonts.

したがって日本語デジタルフォントのデザイン空間は混成的である。通常は一 em の CJK 矩形が日本語の文字枠を定義する一方、座標原点はラテンベースライン互換性のために使われる。レイアウトエンジンは、日本語字形を行に置く前、別の日本語フォントと整列させる前、または和文の行送りを測る前に、原点から CJK em-box の辺および中心への変換を解決しなければならない。ローマンベースラインの原点を日本語のベースラインであるかのように扱うと、フォントごとに異なる、しばしば誤った結果になる。

This section describes the font metrics needed for high-quality Japanese composition. It is aimed at font developers, font-tool developers, and layout-engine implementers. It does not prescribe one visual style or require every Japanese font to use a square design. Rather, it requires the font to state the design it has chosen clearly enough that an application does not have to guess.

ここでは、高品質な日本語組版に必要なフォントメトリックを説明する。対象は、フォント開発者、フォントツール開発者、およびレイアウトエンジン実装者である。特定の視覚的なスタイルを規定したり、すべての日本語フォントに正方形のデザインを要求したりするものではない。フォントが選んだデザインを、アプリケーションが推測せずに使えるだけ明確に記述することを求める。

The OpenType term *ideographic em-box* is used here. *CJK em-box* is used as a convenient synonym when discussing the shared CJK model. This box is not:

ここでは OpenType の用語である *ideographic em-box* を用いる。CJK で共通するモデルを論じる際には、便宜上 *CJK em-box* を同義語として使う。この box は次のものではない。

- the font's `unitsPerEm` value, although a conventional box is often one UPM wide and one UPM high;
- the union of all glyph bounding boxes;
- the advance of an arbitrary full-width glyph; or
- the ideographic character face (ICF, *heikin jizura*), which describes representative ink rather than the layout cell.

- フォントの `unitsPerEm` 値そのもの。ただし従来の box は、多くの場合、幅・高さともに一 UPM である。
- フォント内の全字形の外接矩形の和集合。
- 任意の全角字形のアドバンス。
- レイアウト用の文字枠ではなく、代表的な字面を表す ideographic character face（ICF、平均字面）。

## Font Design Space / フォントのデザイン空間

### The ideographic em-box is a layout coordinate system / 表意文字 em-box はレイアウトの座標系である

The ideographic em-box is the rectangle that defines the standard escapement around the font's full-width ideographic glyphs. In horizontal writing it has a bottom and a top; in vertical writing it has a left and a right. Its center is also a meaningful alignment position. Japanese composition uses those edges and centers as measurement points in their own right.

表意文字 em-box は、フォントの全角表意文字の周囲にある標準的な送り領域を定義する矩形である。横組みでは下辺と上辺を、縦組みでは左辺と右辺を持つ。その中心も意味のある整列位置である。日本語組版では、これらの辺と中心を、それ自体が計測点として用いる。

For a conventional Japanese font, the box is a square of one em. That convention is useful, but it is not the definition. A font may use a non-square box, an offset box, or a box whose geometry changes across a variation axis. What matters is that the intended rectangle, in font units and for each writing direction, is available to the layout system.

従来の日本語フォントでは、この box は１em の正方形であることが多い。しかしこれは有用な慣行であって定義そのものではない。フォントは非正方形の box、オフセットした box、あるいはバリエーション軸により形状が変化する box を持つことができる。重要なのは、意図された矩形がフォント単位で、かつ各組方向について、レイアウトシステムから取得できることである。

In a Japanese line, leading is normally measured from an edge or a center of this box, not merely from the Roman baseline. A line grid and the top and bottom of a text frame likewise commonly refer to em-box geometry. Substituting Latin ascender, descender, or line-gap values for the CJK box makes line placement depend on incidental properties of the font rather than on the Japanese design space.

日本語の行では、行送りは通常、この box の辺または中心から測られるのであって、単にローマンベースラインから測られるのではない。行グリッドやテキストフレームの上下端も、しばしば em-box の幾何形状を基準にする。CJK box の代わりにラテン文字のアセンダ、ディセンダ、または行間値を使うと、行の位置が日本語のデザイン空間ではなく、フォントに偶発的に含まれるラテンメトリックに依存してしまう。

The CJK em-box also supplies the reference cell for full-width composition, including mojikumi. It is therefore distinct from the visible ink of a comma, bracket, kana, or ideograph. A punctuation glyph may occupy only part of its cell; its empty portion is often necessary for controlled inter-character spacing. An engine must not derive the reference cell by inspecting only the ink bounds of the current glyph.

CJK em-box は、文字組み（モジクミ）を含む全角組版の基準セルでもある。したがって、読点、括弧、かな、漢字の見えるインクとは別のものである。約物がセルの一部だけを占めることがあり、その空き部分は制御された字間を作るために必要となる。エンジンは、現在の字形のインク境界だけを調べて基準セルを求めてはならない。

### Required box geometry / 必要な box の幾何情報

A Japanese font intended for high-quality composition should provide the following values in font units:

高品質な組版を意図する日本語フォントは、少なくとも次の値をフォント単位で提供すべきである。

| Purpose | Horizontal text | Vertical text |
| --- | --- | --- |
| CJK em-box edge toward the start of the cross direction | bottom | left |
| CJK em-box edge toward the end of the cross direction | top | right |
| CJK em-box center | halfway between bottom and top | halfway between left and right |
| Standard full-width advance reference | inline advance | inline advance |
| Representative ink area, when provided | ICF bottom and top | ICF left and right |

| 用途 | 横組み | 縦組み |
| --- | --- | --- |
| クロス方向の開始側にある CJK em-box の辺 | 下辺 | 左辺 |
| クロス方向の終了側にある CJK em-box の辺 | 上辺 | 右辺 |
| CJK em-box の中心 | 下辺と上辺の中点 | 左辺と右辺の中点 |
| 標準の全角アドバンス参照 | 行内方向のアドバンス | 行内方向のアドバンス |
| 提供される場合の代表的なインク領域 | ICF の下辺と上辺 | ICF の左辺と右辺 |

The [`BASE`](https://learn.microsoft.com/en-us/typography/opentype/spec/base) table provides the intended portable representation for much of this information. In particular:

この情報の大部分は、[`BASE`](https://learn.microsoft.com/en-us/typography/opentype/spec/base) テーブルによって可搬的に表現できる。特に次のとおりである。

- `HorizAxis.ideo` and `HorizAxis.idtp` define the bottom and top of the ideographic em-box in horizontal layout.
- `VertAxis.ideo` and `VertAxis.idtp` define the left and right of the ideographic em-box in vertical layout. In the usual one-em-wide vertical design, the former is `0` and the latter is `head.unitsPerEm`.
- `icfb` and `icft` can describe the four edges of the ICF. The ICF is valuable for optical alignment of page objects, but it must not replace the em-box for leading, grid placement, or mojikumi.
- `romn` provides the Roman baseline needed to relate Latin glyphs to the Japanese design space.

- `HorizAxis.ideo` と `HorizAxis.idtp` は、横組みでの表意文字 em-box の下辺と上辺を定義する。
- `VertAxis.ideo` と `VertAxis.idtp` は、縦組みでの表意文字 em-box の左辺と右辺を定義する。通常の一 em 幅の縦組みデザインでは、前者は `0`、後者は `head.unitsPerEm` である。
- `icfb` と `icft` は、ICF の四辺を記述できる。ICF はページ上のオブジェクトを視覚的に整列させるのに有用だが、行送り、グリッド配置、またはモジクミで em-box の代わりにしてはならない。
- `romn` は、ラテン字形を日本語のデザイン空間に関連付けるためのローマンベースラインを提供する。

OpenType stores advances on individual glyphs in `hmtx` and `vmtx`; it does not provide one universally implemented field that declares the CJK reference advance for mojikumi. A font that depends on a particular full-width reference—commonly the ideographic space, U+3000—must keep that reference stable and distinguish it from narrow punctuation or proportional alternates. A layout engine must treat the declared CJK box and the chosen advance reference as separate metrics.

OpenType は個々の字形のアドバンスを `hmtx` と `vmtx` に保持するが、モジクミのための CJK 基準アドバンスを一つの、広く実装されたフィールドとしては定義していない。特定の全角参照（しばしば表意文字空白 U+3000）に依存するフォントは、その参照を安定に保ち、狭い約物やプロポーショナルな代替字形と区別しなければならない。レイアウトエンジンは、宣言された CJK box と選択されたアドバンス参照を別個のメトリックとして扱う必要がある。

For a conventional square CJK design, the horizontal `ideo`/`idtp` distance and the vertical `ideo`/`idtp` distance are one UPM. The center should be integral in font units where possible, so that centering at different sizes does not introduce avoidable rounding differences.

通常の正方形 CJK デザインでは、横組みの `ideo`/`idtp` 間と縦組みの `ideo`/`idtp` 間はいずれも一 UPM である。異なるサイズで中心揃えを行った際に不要な丸め差が出ないよう、可能な場合は中心をフォント単位で整数にすべきである。

The font should keep the relevant values coherent across the `BASE`, `OS/2`, and `hhea` tables. In practice, some applications still recover the horizontal ideographic box from `OS/2.sTypoDescender` and `OS/2.sTypoAscender`, while others use `BASE`. A CJK font whose values disagree can be positioned differently by otherwise conforming applications. The [OpenType baseline-tag guidance](https://learn.microsoft.com/en-us/typography/opentype/spec/baselinetags) specifically recommends making these values agree when they denote the same ideographic-box edges.

フォントは、`BASE`、`OS/2`、`hhea` の関連する値を整合させるべきである。実際には、あるアプリケーションは横組みの表意文字 box を `OS/2.sTypoDescender` と `OS/2.sTypoAscender` から求め、別のアプリケーションは `BASE` を使う。CJK フォント内でこれらの値が食い違うと、それ以外は適合しているアプリケーションでも異なる位置に組まれる可能性がある。[OpenType の baseline tag 指針](https://learn.microsoft.com/en-us/typography/opentype/spec/baselinetags)も、同じ表意文字 box の辺を表す場合には、これらの値を一致させることを推奨している。

### The ICF box describes a representative character face / ICF box は代表的な字面を記述する

The ideographic character face (ICF) box is frequently misunderstood as the union of every glyph's ink bounds in a font. It is not. Such a union is dominated by exceptional glyphs, marks, ornaments, and symbols, and says little about how an ordinary ideographic character should align with surrounding text.

ideographic character face（ICF）box は、フォント内のすべての字形のインク境界を合成したものと誤解されがちである。しかしそうではない。そのような和集合は、例外的な字形、マーク、装飾、記号に支配され、通常の漢字が周囲のテキストとどのように整列すべきかをほとんど示さない。

The ICF box is a placeholder for the *average ideographic character face*: the representative visible area of a full-width ideograph within the CJK em-box. It answers two practical questions for a layout system:

ICF box は *平均的な漢字字面* のためのプレースホルダである。すなわち、CJK em-box 内にある全角漢字の代表的な可視領域である。これはレイアウトシステムに対し、次の二つの実用的な問いに答える。

- At what offset, relative to this font's baseline and CJK em-box, should the visible face of an ideograph sit?
- At what scale should that face be treated when it is harmonized with glyphs from this font or from another font?

- このフォントのベースラインおよび CJK em-box に対して、漢字の可視字面はどのオフセットに置かれるべきか。
- その字面を、このフォントまたは別のフォントの字形と調和させるとき、どのスケールとして扱うべきか。

For a font containing ideographs, the ICF should be derived from representative full-width ideographs: select glyphs that are large, regular, and close to square, then derive an average character face from them. Kana outlines must not be included in that sample or average, even in a CJK font that contains kana. The ICF should not be based on a rare extreme, a punctuation mark, or the union of all outlines. The resulting box is usually centered within the em-box, but the font may deliberately specify an asymmetric or non-square face.

漢字を含むフォントでは、ICF は代表的な全角漢字から求めるべきである。大きく、規則的で、正方形に近い字形を選び、そこから平均的な字面を導く。かなのアウトラインは、その CJK フォントがかなを含む場合でも、このサンプルまたは平均に加えてはならない。ICF は、まれな極端例、約物、または全アウトラインの和集合に基づくべきではない。得られる box は通常 em-box の中心に置かれるが、フォントは意図的に非対称または非正方形の字面を指定できる。

The same metric remains meaningful when the font contains no ideographs. A kana-only font can use the ICF to state the ideographic face with which its kana are intended to harmonize. A Latin or other non-CJK font can use it to state the size and baseline offset of the ideographic face that should be used when its glyphs share a Japanese line. In those cases, the ICF is not a measurement of absent outlines; it is a design declaration of the intended CJK counterpart.

漢字を含まないフォントでも、このメトリックは意味を持つ。かな専用フォントは、かなが調和すべき漢字字面を示すために ICF を使用できる。ラテンフォントまたは他の非 CJK フォントは、その字形が日本語の行を共有するときに用いるべき漢字字面のサイズとベースラインオフセットを示すために ICF を使える。この場合の ICF は、存在しないアウトラインの測定値ではなく、意図された CJK 側の対応物についてのデザイン宣言である。

Thus the ICF provides a stable visual reference across fonts: it distinguishes the CJK cell from the representative ink inside it, and it allows an engine to align page objects, compare apparent sizes, or harmonize a kana-only or Latin font with Japanese text without pretending that all glyphs have the same bounds. It is normally an optical alignment metric, not the metric from which Japanese leading or mojikumi cells are calculated.

このように ICF は、フォントをまたいだ安定した視覚的参照を提供する。CJK セルとその中にある代表的なインクを分離し、すべての字形が同一の境界を持つと見なすことなく、エンジンがページオブジェクトを整列し、見かけの大きさを比較し、かな専用またはラテンフォントを日本語テキストと調和させることを可能にする。ICF は通常、視覚的な整列のためのメトリックであり、日本語の行送りやモジクミのセルを算出するメトリックではない。

### Non-square, variable, and exceptional designs / 非正方形、可変、および例外的なデザイン

The square one-em model is a default, not a license for an engine to discard font data that says otherwise. A Japanese font may legitimately depart from that model in several independent ways:

一 em の正方形モデルは既定値であり、異なるフォントデータをエンジンが捨ててよい理由ではない。日本語フォントは、次のように、このモデルから正当に離れることができる。

- The design box may be anisotropic: its inline width and cross-direction height differ. This is useful, for example, for a vertically condensed newspaper design.
- A variable font may change the em-box geometry at different instances. The corresponding `BASE` coordinates must then carry variation data; a default-instance value is not sufficient.
- A font may keep a stable one-em design box while varying the advances or the ink placement of kana and punctuation. The stable box remains the reference for operations that use the design cell, even though the current glyph advance is different.
- A font may use narrow punctuation or a non-standard ideographic-space advance. Such glyph behavior does not, by itself, define a smaller CJK em-box.

- デザイン box は異方的であり得る。すなわち、行内方向の幅とクロス方向の高さが異なる。これは、たとえば縦方向に圧縮した新聞用デザインに有用である。
- バリアブルフォントは、異なるインスタンスで em-box の幾何形状を変えることができる。この場合、対応する `BASE` 座標はバリエーションデータを持たなければならず、デフォルトインスタンスの値だけでは足りない。
- フォントは、かなや約物のアドバンスまたはインク位置を変えつつ、安定した一 em のデザイン box を保つことができる。その box は、現在の字形アドバンスが異なっていても、デザインセルを使う処理の基準であり続ける。
- 狭い約物または非標準の表意文字空白アドバンスを持つフォントがある。その字形上の振る舞いだけで、CJK em-box が小さいと結論してはならない。

These distinctions are not theoretical. Momochidori demonstrates a variable, anisotropic CJK-box case. Neokuro demonstrates a fixed one-em CJK box whose width-axis instances can narrow glyph advances and move ink inside that stable cell. Kazuraki demonstrates why a layout engine cannot assume that punctuation or ideographic-space advances have the usual relationship to a square cell. A correct implementation must retain the font's declared box and resolve advances, glyph ink, and mojikumi rules independently.

これは理論上だけの区別ではない。Momochidori は可変で異方的な CJK box の例である。Neokuro は、一 em の CJK box を固定したまま、幅軸のインスタンスで字形アドバンスを狭め、インクをその安定したセル内で移動させる例である。Kazuraki は、エンジンが約物または表意文字空白のアドバンスと正方形セルの通常の関係を仮定できないことを示す。正しい実装は、フォントが宣言した box を保持し、アドバンス、字形インク、モジクミ規則を独立して解決しなければならない。

For variable fonts, an author must decide which quantities are designed to vary: the CJK em-box, the ICF, the Roman baseline, script extents, full-width advances, or some combination. The answer must be represented in the font's variation-aware metric data. It must not be inferred from a named instance, from a sampled glyph, or from the fact that an axis is called `wdth`.

バリアブルフォントでは、作者は CJK em-box、ICF、ローマンベースライン、文字体系のエクステント、全角アドバンスのどれを変化させるかを決めなければならない。その答えはバリエーションに対応したメトリックデータで表すべきである。名前付きインスタンス、サンプル字形、または軸名が `wdth` であるという事実から推測してはならない。

### Font metrics are preferable to engine guesses / フォントメトリックはエンジンの推測より優先される

Many deployed fonts omit usable `BASE` data. Many font-production tools do not expose ideographic-box and ICF values conveniently, and many layout APIs and engines ignore the data when it is present. As a result, engines often calculate substitute metrics themselves. This is a necessary compatibility measure, but it is not a satisfactory definition of the font's design.

実際に配布されている多くのフォントには、利用可能な `BASE` データがない。多くのフォント制作ツールは表意文字 box や ICF の値を簡単には公開せず、値が存在しても、多くのレイアウト API やエンジンはそれを無視する。そのためエンジンは代替メトリックを自ら計算することが多い。これは互換性のために必要な措置ではあるが、フォントデザインの十分な定義ではない。

An engine resolving a CJK em-box should use the following order of preference:

CJK em-box を解決するエンジンは、次の優先順位を用いるべきである。

1. Use the font-authored, variation-resolved ideographic em-box coordinates.
2. For a CJK font without those coordinates, use the compatible CJK fallback defined by OpenType: the typographic ascender and descender together with the UPM-wide vertical box.
3. If the font is incomplete or contradictory, apply a documented, conservative heuristic and mark the result as inferred. The ideographic-space advance and carefully chosen exemplar glyphs can be useful evidence, but neither is a general definition of the box.
4. Permit an application or document to override a known-bad or incomplete font metric. The override should identify whether it changes the em-box, the ICF, an advance reference, a baseline, or a line policy; it should not be an unexplained global offset.

1. フォントが作成し、現在のバリエーションに解決された表意文字 em-box 座標を使用する。
2. それらの座標を持たない CJK フォントでは、OpenType が定める互換的な CJK フォールバック、すなわち typographic ascender と descender、および UPM 幅の縦組み box を使用する。
3. フォント情報が不完全または矛盾している場合は、文書化された保守的なヒューリスティックを適用し、その結果が推測値であることを示す。表意文字空白のアドバンスや慎重に選んだ例示字形は有用な証拠になり得るが、いずれも box の一般的な定義ではない。
4. 既知の不正確または不完全なフォントメトリックを、アプリケーションまたは文書が上書きできるようにする。その上書きは、em-box、ICF、アドバンス参照、ベースライン、行ポリシーのどれを変えるのかを明示すべきであり、理由不明のグローバルオフセットであってはならない。

An inference algorithm must distinguish the following cases: a genuinely non-square em-box; a fixed em-box with variable glyph advances; a font whose full-width punctuation is intentionally narrow; a font that lacks a representative sample glyph; and a font that contains no ideographs but is designed to harmonize with one. Treating all of them as a default square based on U+3000, a glyph bounding box, or `hhea` metrics produces visibly wrong results in real fonts.

推測アルゴリズムは、真に非正方形の em-box、字形アドバンスが可変でも em-box が固定のフォント、全角約物が意図的に狭いフォント、代表的なサンプル字形がないフォント、表意文字を含まないが表意文字と調和するよう設計されたフォントを区別しなければならない。これらすべてを U+3000、字形境界、または `hhea` メトリックに基づく既定の正方形として扱うと、実在するフォントで視覚的に誤った結果を生む。

## Glyph Alignment, Line Height and Positioning within the Line / 字形の整列、行高、および行内配置

Japanese composition should align CJK glyph runs by their resolved em-boxes. The baseline that happens to be used to place an individual outline is an internal font coordinate; it is not sufficient as the line's universal alignment reference.

日本語組版では、CJK 字形のランを、解決済みの em-box によって整列すべきである。個々のアウトラインを配置するために用いられるベースラインはフォント内部の座標であり、行全体に通用する整列基準としては十分ではない。

When CJK runs of different point sizes share a Japanese line, the normal policy is to scale each run's em-box and align the box centers. This preserves the intended visual center of each glyph cell. A composition system may instead offer an edge-aligned policy—for example, aligning em-box tops or bottoms to a grid or to a frame edge—but that choice must be explicit. It must not silently become Roman-baseline alignment because one run contains Latin text or because a font lacks ordinary typographic ascent and descent values.

異なるポイントサイズの CJK ランが一つの日本語行を共有するとき、通常の方針は、各ランの em-box を拡大・縮小して、その中心を整列させることである。これにより、各字形セルに意図された視覚的中心が保たれる。組版システムは、たとえば em-box の上辺または下辺をグリッドやフレーム端にそろえるため、辺をそろえる方針を提供してもよい。しかし、その選択は明示的でなければならない。あるランにラテン文字が含まれる、またはフォントに通常の typographic ascender / descender がないという理由で、暗黙にローマンベースライン整列へ変わってはならない。

The same distinction applies to line leading:

同じ区別は行送りにも適用される。

- In a Japanese leading model, baseline-to-baseline distance is derived from selected em-box edges or centers and the specified line gap.
- The first and last line of a frame may need separate treatment so that their em-box edges, rather than accidental Roman ascenders or descenders, meet the intended frame or grid boundaries.
- Glyph extents still matter for collision avoidance, annotations, ruby, and clipping. They are an additional constraint on the line, not a replacement for its CJK alignment model.

- 日本語の行送りモデルでは、ベースライン間の距離は、選択された em-box の辺または中心と、指定された行間から導かれる。
- フレームの先頭行と最終行は、偶発的なローマンアセンダやディセンダではなく、em-box の辺が意図したフレーム端またはグリッド境界に達するよう、特別な扱いを必要とすることがある。
- 字形エクステントは、衝突回避、注釈、ルビ、クリッピングにとって依然重要である。ただしそれは行に対する追加の制約であり、CJK 整列モデルの代わりではない。

An engine should preserve this model in both horizontal and vertical writing. In vertical text, the corresponding left, right, and center positions of the em-box take the role that top, bottom, and center take in horizontal text.

エンジンは、このモデルを横組みと縦組みの両方で維持すべきである。縦組みでは、em-box の左、右、中心が、横組みにおける上、下、中心に対応する役割を持つ。

## Fonts Contain Both Monospaced and Proportional Glyphs / フォントには等幅字形とプロポーショナル字形が共存する

Japanese fonts normally contain both full-width glyphs that participate in a CJK cell model and proportional glyphs that do not. The distinction is fundamental, but it must not be confused with the distinction between an em-box, a glyph advance, and a glyph's ink bounds.

日本語フォントには通常、CJK セルモデルに参加する全角字形と、そうではないプロポーショナル字形の両方が含まれる。この区別は基本的なものだが、em-box、字形アドバンス、字形のインク境界の区別と混同してはならない。

A full-width ideograph normally advances by the inline dimension of the resolved CJK em-box. Its design cell remains meaningful even when the outline is smaller than the cell. Many kana and punctuation glyphs also use that cell, often with intentionally asymmetric white space needed for mojikumi. Proportional Latin, numerals, symbols, and some kana or punctuation instead have their own advances. They may be centered within, aligned to an edge of, or positioned relative to the CJK design space, but their advance must not be inflated to the CJK cell merely because they occur in a Japanese line.

全角の表意文字は通常、解決済み CJK em-box の行内方向の寸法だけアドバンスする。アウトラインがセルより小さくても、そのデザインセルは意味を持ち続ける。多くのかなと約物もそのセルを使い、モジクミに必要な意図的に非対称な空白を持つことがある。これに対し、プロポーショナルなラテン文字、数字、記号、一部のかなまたは約物は独自のアドバンスを持つ。これらは CJK デザイン空間内で中心揃え、辺揃え、または相対配置され得るが、日本語行に現れたからといって、そのアドバンスを CJK セルまで広げてはならない。

The engine therefore needs at least three independent measurements for every run:

したがってエンジンは、各ランについて少なくとも三つの独立した測定値を必要とする。

| Measurement | What it controls | What must not be inferred from it |
| --- | --- | --- |
| CJK em-box | line placement, grid alignment, mixed-size alignment, and the reference cell | the current glyph's advance or ink bounds |
| Glyph advance | the inline position of the next glyph | the size or origin of the CJK em-box |
| Glyph ink bounds | collision, selection, decoration, and optical fitting | the standard character cell or average ideographic face |

| 測定値 | 制御するもの | そこから推測してはならないもの |
| --- | --- | --- |
| CJK em-box | 行配置、グリッド整列、異サイズ整列、基準セル | 現在の字形のアドバンスまたはインク境界 |
| 字形アドバンス | 次の字形の行内位置 | CJK em-box の大きさまたは原点 |
| 字形インク境界 | 衝突、選択範囲、装飾、視覚的フィット | 標準の文字セルまたは平均表意文字字面 |

Mojikumi tables express many spacing adjustments as fractions of a CJK reference cell. A layout engine must resolve which reference the table requires—an authored fixed em-box, the current full-width advance, or a deliberately separate ideographic-space reference—and keep that decision stable within the font's design. It must not rescale a table value just because a particular bracket or punctuation outline has become narrow.

モジクミテーブルでは、多くの空き量調整を CJK 基準セルの分数として表す。レイアウトエンジンは、テーブルが要求する参照が、作成された固定 em-box なのか、現在の全角アドバンスなのか、意図的に別にした表意文字空白参照なのかを解決し、その判断をフォントのデザイン内で安定に保たなければならない。特定の括弧または約物のアウトラインが狭くなったというだけで、テーブル値を再スケーリングしてはならない。

Proportional-metrics features such as `palt`, `halt`, and `vpal` may deliberately change selected glyph advances. They are useful typography controls, but they do not redefine the CJK em-box, the ICF, or Japanese line leading. After such a feature is applied, the engine must use the adjusted advances for inline placement and the original resolved em-box for the line model, unless the font explicitly provides variation-aware box data that says the box itself changes.

`palt`、`halt`、`vpal` などのプロポーショナルメトリック機能は、選択された字形のアドバンスを意図的に変えることがある。これらは有用な組版制御だが、CJK em-box、ICF、日本語の行送りを再定義するものではない。このような機能を適用した後、フォントが box 自体の変化を示すバリエーション対応 box データを明示的に提供しない限り、エンジンは調整後のアドバンスを行内配置に用い、元の解決済み em-box を行モデルに用いなければならない。

## Adjusting the Metrics of the Latin Glyphs / ラテン字形のメトリック調整

Japanese fonts commonly include Latin glyphs, and Japanese documents commonly mix them with separately selected Latin fonts. The CJK em-box therefore needs an explicit relationship to the Roman baseline and to Latin metrics.

日本語フォントにはラテン字形が含まれることが多く、日本語文書では別に選択されたラテンフォントと混在することも多い。そのため、CJK em-box とローマンベースラインおよびラテンメトリックとの関係を明示する必要がある。

A Japanese font that includes Latin should define the Roman baseline, Latin ascender and descender behavior, and Latin glyph scale so that the Latin run appears deliberate within the Japanese em-box. The important result is not that the Latin baseline is numerically zero: it is that the relationship between the Roman baseline and the CJK box is stable and can be reproduced when a different Latin font is used on the same line.

ラテン字形を含む日本語フォントは、ラテンランが日本語 em-box 内で意図的に見えるよう、ローマンベースライン、ラテンのアセンダ・ディセンダの挙動、およびラテン字形のスケールを定義すべきである。重要なのは、ラテンベースラインの数値がゼロかどうかではない。ローマンベースラインと CJK box の関係が安定しており、同じ行で別のラテンフォントを用いた場合にも再現可能であることである。

In `BASE`, the `romn` and ideographic baseline coordinates should be supplied for the relevant scripts in a common coordinate system. The font should also provide its script extents where they are needed for safe line composition. This lets a layout engine align Latin with Japanese according to the Japanese line model, while still respecting the Latin font's own baseline and extents.

`BASE` では、`romn` と表意文字ベースラインの座標を、関係する文字体系について共通の座標系で提供すべきである。安全な行組版に必要な場合には、文字体系のエクステントも提供すべきである。これにより、レイアウトエンジンはラテンフォント固有のベースラインとエクステントを尊重しながら、日本語の行モデルに従ってラテン文字を日本語と整列できる。

The responsibility is shared:

責任は共有される。

- A Japanese font should state where its Latin baseline belongs relative to its CJK em-box.
- A Latin-only font intended for CJK use may provide ideographic baseline information so that an engine can align it with Japanese text.
- A layout engine should resolve the relationship from font metrics when available, then choose the line's dominant alignment model explicitly. It should not assume that matching point sizes or matching UPM values imply matching perceived size or baseline offset.

- 日本語フォントは、そのラテンベースラインが CJK em-box に対してどこにあるかを示すべきである。
- CJK での使用を意図するラテン専用フォントは、エンジンが日本語テキストとの整列に使える表意文字ベースライン情報を提供できる。
- レイアウトエンジンは、利用可能ならフォントメトリックから関係を解決し、行で支配的な整列モデルを明示的に選ぶべきである。ポイントサイズまたは UPM が同じだからといって、知覚される大きさやベースラインオフセットも一致するとは仮定してはならない。

This relationship affects more than the appearance of a single line. It determines whether mixed Japanese/Latin text shares a grid, whether line gaps remain even, and whether a change of Latin fallback font changes the position of adjacent Japanese glyphs.

この関係は一行の見た目だけに影響するものではない。日本語とラテン文字の混在テキストがグリッドを共有できるか、行間が均一に保たれるか、ラテンのフォールバックフォントを変えたときに隣接する日本語字形の位置が変わるかを左右する。

For a separately selected Latin font, the ICF supplies the missing visual reference: it states the scale and offset of the ideographic face with which that Latin design is intended to harmonize. The Japanese line model can then place the Latin font's Roman baseline at the declared offset and compare its intended face against the Japanese ICF, rather than relying on coincidental equality of point size, UPM, cap height, or ascender values. Applications may still offer a user-selected optical-size or baseline override, but that override should be expressed relative to the declared metrics.

別に選択されたラテンフォントの場合、ICF が欠けている視覚的参照を補う。すなわち、そのラテンデザインが調和すべき表意文字字面のスケールとオフセットを示す。こうして日本語の行モデルは、ラテンフォントのローマンベースラインを宣言されたオフセットに置き、その意図された字面を日本語 ICF と比較できる。ポイントサイズ、UPM、キャップハイト、アセンダの偶然の一致に頼る必要はない。アプリケーションはユーザー選択の optical-size またはベースライン上書きを提供してもよいが、その上書きは宣言されたメトリックに対して表現すべきである。

### Other scripts and future cross-script harmonization / 他の文字体系と将来の文字体系間調和

The `BASE` table was designed to align multiple scripts and can contain script-specific baselines and min/max extents. It is therefore the natural basis for cross-script harmonization. Its registered baseline vocabulary and current implementation practice, however, do not yet provide a complete, widely supported set of placement metrics for Arabic, Devanagari and other Indic scripts, Korean-specific use cases, and many other writing systems. A hanging baseline can describe an important aspect of Indic layout, for example, but it is not a complete account of the script's placement zone, extents, or relationship to a CJK cell.

`BASE` テーブルは複数文字体系の整列のために設計され、文字体系ごとのベースラインおよび最小・最大エクステントを保持できる。したがって、文字体系間の調和にとって自然な基盤である。しかし、登録済みベースライン語彙と現在の実装状況は、アラビア文字、デーヴァナーガリーその他のインド系文字、韓国語固有の利用例、その他多くの書記体系について、完全で広くサポートされた配置メトリックの組をまだ提供していない。たとえばハンギングベースラインはインド系組版の重要な側面を表せるが、文字体系の配置領域、エクステント、CJK セルとの関係を完全には記述しない。

When a portable metric model is defined for another script, a font intended for Japanese mixed-script composition should make the relationship explicit. At minimum, the model needs:

別の文字体系のための可搬的なメトリックモデルが定義されるとき、日本語との混植を意図するフォントは、その関係を明示すべきである。少なくともそのモデルには次が必要である。

- the script's default alignment position or baseline;
- the script's normal top, bottom, or side extents for line composition;
- a definition of the script's placement zone or reference box when a baseline alone is not enough; and
- the offset of those positions relative to the CJK em-box edges and center for the relevant writing direction.

- 文字体系の既定の整列位置またはベースライン。
- 行組版のための通常の上、下、または側方のエクステント。
- ベースラインだけでは不十分な場合の、文字体系の配置領域または基準 box の定義。
- 組方向に応じた、それらの位置と CJK em-box の辺および中心とのオフセット。

Those values must be authored rather than reconstructed from the union of glyph outlines. Arabic joining behavior, Indic marks, Korean syllable design, and language- or feature-specific alternates all make an outline-only inference unstable. Where a script requires larger extents for a language system or OpenType feature, the font should use script-, language-, or feature-specific extent data rather than forcing every line to use the largest possible bounding box.

これらの値は、アウトラインの和集合から再構成するのではなく、フォントが作成しなければならない。アラビア文字の接続、インド系文字のマーク、韓国語音節のデザイン、言語または機能に固有の異体は、アウトラインだけによる推測を不安定にする。特定の言語システムまたは OpenType 機能でより大きなエクステントが必要な場合は、すべての行に最大の境界 box を強いるのではなく、文字体系、言語、機能に固有のエクステントデータを使用すべきである。

The goal is not to make every script fit a square CJK cell. The goal is to let an engine answer, reproducibly: *where should this script sit in a Japanese line, how large is its normal placement zone, and what extra extent does it require?*

目的は、すべての文字体系を正方形の CJK セルに押し込むことではない。エンジンが「この文字体系は日本語の行のどこに置くべきか、通常の配置領域はどれほどか、どの追加エクステントを必要とするか」を再現可能に答えられるようにすることである。

## Vertical Layout / 縦組み

Vertical Japanese composition is not horizontal composition turned sideways. It uses the vertical CJK em-box, its left and right edges, and its center as the reference for columns, frame edges, leading, and the placement of upright glyphs. A font must therefore supply or preserve direction-aware box geometry and vertical metrics; rotating horizontal ink bounds or using horizontal Roman ascent and descent is insufficient.

縦組みの日本語組版は、横組みを横倒しにしたものではない。縦組みの CJK em-box、その左辺・右辺・中心を、列、フレーム端、行送り、直立字形の配置の基準として使う。そのためフォントは、組方向に応じた box の幾何情報と縦組みメトリックを提供または保持しなければならない。横組みのインク境界を回転する、または横組みのローマンアセンダ・ディセンダを使うだけでは不十分である。

Full-width Japanese glyphs are ordinarily set upright and positioned within the vertical CJK cell. The appropriate reference for an upright glyph is the vertical em-box center or a deliberately selected edge. The appropriate reference for a rotated glyph is also the resolved em-box center, not the center of its ink bounds. This prevents a glyph from appearing to move merely because its design has asymmetric side bearings or because its glyph is replaced with a vertical form.

全角の日本語字形は通常、直立したまま縦組み CJK セルに配置される。直立字形の適切な基準は、縦組み em-box の中心または意図的に選ばれた辺である。回転する字形についても、適切な基準はインク境界の中心ではなく解決済み em-box の中心である。このため、デザインに非対称なサイドベアリングがある、または縦組み字形に置換されるというだけで、字形が動いて見えることを防げる。

Latin, digits, punctuation, and symbols require a font and engine to distinguish several cases: a glyph may remain upright; it may be rotated; it may have a purpose-designed vertical alternate; or it may participate in a tate-chu-yoko run managed by the layout system. The vertical Roman baseline and the relationship of the rotated or upright glyph to the CJK em-box must be known to place each case consistently. A font's horizontal Roman baseline alone does not answer this question.

ラテン文字、数字、約物、記号については、フォントとエンジンがいくつかの場合を区別する必要がある。字形は直立のままの場合、回転する場合、縦組み用に設計された代替字形を持つ場合、またはレイアウトシステムが管理する縦中横ランに参加する場合がある。各場合を一貫して配置するには、縦組みのローマンベースラインと、回転または直立した字形と CJK em-box の関係を知る必要がある。フォントの横組みローマンベースラインだけでは、この問いに答えられない。

Vertical advances also remain independent of the em-box. A font can provide full-height default CJK glyphs, proportional vertical alternates, and variable-font instances with different advances without changing its underlying design cell. The engine must resolve vertical advances after substitutions and positioning have been applied, while preserving the appropriate em-box as the reference for Japanese line and grid placement.

縦組みアドバンスも em-box とは独立している。フォントは、全高の既定 CJK 字形、プロポーショナルな縦組み代替字形、異なるアドバンスを持つバリアブルフォントインスタンスを提供しても、基礎となるデザインセルを変えないことができる。エンジンは置換と位置調整が適用された後に縦組みアドバンスを解決しつつ、日本語の行およびグリッド配置の基準として適切な em-box を保たなければならない。

Vertical layout makes missing metrics especially visible. The most common failures are a column that is placed using horizontal typographic ascender/descender values; punctuation that rotates around its ink instead of its cell; Latin that is centered on an unrelated Roman origin; and a variable font whose horizontal metrics are reused for an upright vertical instance. These are metric-resolution failures, not merely glyph-substitution failures.

縦組みでは、メトリック欠落が特に目立つ。よくある失敗は、横組みの typographic ascender / descender を用いて列を置くこと、セルではなくインクを中心に約物を回転すること、無関係なローマン原点を中心にラテン文字を置くこと、直立縦組みインスタンスにバリアブルフォントの横組みメトリックを再利用することである。これらは単なる字形置換の失敗ではなく、メトリック解決の失敗である。

## OpenType Features / OpenType 機能

OpenType `GSUB` and `GPOS` features allow a Japanese font to supply forms and positioning that cannot be represented by a single default outline and advance. A high-quality layout engine must apply the features appropriate to the selected script, language, writing direction, and document setting, then use the resulting glyphs and advances without discarding the font's em-box and baseline metrics.

OpenType の `GSUB` と `GPOS` 機能により、日本語フォントは、単一の既定アウトラインとアドバンスだけでは表せない字形および位置調整を提供できる。高品質なレイアウトエンジンは、選択された文字体系、言語、組方向、文書設定に適切な機能を適用し、その結果得られた字形とアドバンスを使う一方で、フォントの em-box およびベースラインメトリックを捨ててはならない。

Features especially relevant to Japanese fonts include:

日本語フォントに特に関係する機能には、次のものがある。

- `vert` and `vrt2` select vertical forms and rotated vertical alternates. `vrt2` covers a wider set of proportional and half-width glyphs; an engine should follow the feature's registered interaction rules rather than applying both indiscriminately.
- `vkna` selects kana forms drawn specifically for vertical use. These alternates improve fit and colour in vertical text but do not themselves define a different CJK em-box.
- `vkrn`, `vpal`, and `vapk` provide vertical kerning and proportional vertical metrics. Their interaction matters: kerning intended for a proportional vertical form must not be applied to the corresponding fixed-height form.
- `palt`, `halt`, and related width features select proportional or alternate advances in horizontal composition. They change inline spacing for the affected glyphs, not the line's CJK design space.
- `ruby` selects kana forms designed for ruby annotation. Ruby positioning, scaling, and collision handling remain layout responsibilities; the feature provides the designed glyph form.
- `jp78`, `jp83`, `jp90`, `jp04`, `nlck`, `trad`, and related form-selection features allow a font to represent historical, regional, or stylistic choices. Required ligatures and contextual substitutions must also be honored where the font defines them.

- `vert` と `vrt2` は、縦組み字形および回転させる縦組み代替字形を選択する。`vrt2` はより広い範囲のプロポーショナル字形と半角字形を対象とするため、エンジンは両方を無差別に適用するのではなく、登録された機能相互作用規則に従うべきである。
- `vkna` は、縦組み専用に描かれたかな字形を選択する。これらの代替字形は縦組みのフィットと文字色を改善するが、それ自体が異なる CJK em-box を定義するわけではない。
- `vkrn`、`vpal`、`vapk` は、縦組みカーニングとプロポーショナルな縦組みメトリックを提供する。その相互作用は重要である。プロポーショナルな縦組み字形のためのカーニングを、対応する固定高字形に適用してはならない。
- `palt`、`halt`、および関連する幅の機能は、横組みにおけるプロポーショナルまたは代替アドバンスを選択する。これらは対象字形の行内間隔を変えるが、行の CJK デザイン空間を変えるものではない。
- `ruby` は、ルビ注釈用に設計されたかな字形を選択する。ルビの配置、拡大縮小、衝突回避は引き続きレイアウト側の責任であり、この機能は設計済みの字形を提供する。
- `jp78`、`jp83`、`jp90`、`jp04`、`nlck`、`trad`、および関連する字形選択機能は、歴史的、地域的、または様式的な選択をフォント内に表現できるようにする。フォントが定義する場合は、必須リガチャおよび文脈依存置換も尊重しなければならない。

The feature data must be authored and tested together with the metrics. A vertical alternate can have different ink bounds, a proportional alternate can have a different advance, and a variable-font feature substitution can select a different glyph design. None of those facts authorizes an engine to recompute the CJK em-box from the substituted glyph. Conversely, a feature that changes an advance must be reflected before line breaking, mojikumi, and optical kerning are finalized.

機能データはメトリックとともに作成し、検証しなければならない。縦組み代替字形は異なるインク境界を持つことがあり、プロポーショナル代替字形は異なるアドバンスを持つことがあり、バリアブルフォントの機能置換は別の字形デザインを選択することがある。これらのいずれも、置換された字形から CJK em-box を再計算することをエンジンに許すものではない。逆に、アドバンスを変える機能は、改行、モジクミ、視覚的カーニングを確定する前に反映されなければならない。

Font tools should make these features inspectable by script and language system, and should preserve their lookup data and interaction constraints. Layout engines should expose the relevant document controls and report which features were applied. A feature tag is not a substitute for the missing baseline, em-box, ICF, and extent data described above.

フォントツールは、これらの機能を文字体系および言語システムごとに検査可能にし、lookup データと相互作用上の制約を保存すべきである。レイアウトエンジンは、関係する文書上の制御を公開し、どの機能が適用されたかを報告すべきである。機能タグは、ここまでで述べたベースライン、em-box、ICF、エクステントのデータ欠落を補うものではない。

## Requirements for font and tool implementers / フォントおよびツール実装者への要件

To support robust Japanese composition, font production and validation tools should be able to create, inspect, preserve, and test the following data:

堅牢な日本語組版を支援するため、フォント制作および検証ツールは、少なくとも次のデータを作成、検査、保持、テストできるべきである。

1. Horizontal and vertical CJK em-box edges, their centers, and the declared full-width advance reference.
2. ICF edges, kept distinct from em-box edges.
3. The relationship of the Roman baseline to the CJK em-box, including vertical-text behavior where applicable.
4. Script-specific baselines and min/max extents for all scripts intentionally supported by the font.
5. Variation deltas for every metric that varies by instance, including `BASE` values.
6. A declaration or reliably inspectable result indicating whether the CJK em-box is fixed while glyph advances vary.
7. Validation across representative variable-font instances and in both writing directions.

1. 横組み・縦組みの CJK em-box の辺、中心、および宣言された全角アドバンス参照。
2. em-box の辺と区別された ICF の辺。
3. 縦組みでの挙動を含む、ローマンベースラインと CJK em-box の関係。
4. フォントが意図してサポートするすべての文字体系の、文字体系固有のベースラインおよび最小・最大エクステント。
5. `BASE` 値を含む、インスタンスごとに変わるすべてのメトリックのバリエーションデルタ。
6. 字形アドバンスが変化しても CJK em-box が固定かどうかを示す宣言、または信頼できる検査可能な結果。
7. 代表的なバリアブルフォントインスタンスと、両方の組方向にわたる検証。

Layout engines should expose the resolved values to clients and should report when a value is inferred rather than read from the font. A client needs to be able to diagnose a difference between a font with an intentionally non-square box, a font with incomplete data, and an engine that chose an incompatible fallback.

レイアウトエンジンは、解決済みの値をクライアントに公開し、値がフォントから読み取られたものではなく推測されたものである場合は、そのことを報告すべきである。クライアントは、意図的に非正方形の box を持つフォント、不完全なデータを持つフォント、互換性のないフォールバックを選んだエンジンの違いを診断できる必要がある。

## Conformance-oriented summary / 適合性に関する要約

A Japanese font suitable for high-quality layout must make its ideographic em-box available as an intentional, direction-aware metric. A layout engine must use that metric as the reference for Japanese glyph placement, mixed-size alignment, leading, grid placement, and full-width composition; it must not substitute a Roman baseline, a global glyph bounding box, or an arbitrary glyph advance.

高品質なレイアウトに適した日本語フォントは、表意文字 em-box を、意図された組方向対応のメトリックとして利用可能にしなければならない。レイアウトエンジンは、そのメトリックを日本語字形の配置、異サイズ整列、行送り、グリッド配置、全角組版の基準として使用しなければならない。ローマンベースライン、グローバルな字形境界、任意の字形アドバンスで置き換えてはならない。

The conventional square one-em CJK box remains a useful default. It is not a universal truth of Japanese fonts. Font authors must be able to express other designs, including non-square and variable boxes, and engines must preserve a fixed design box when a font intentionally varies only advances or glyph ink. Explicit metrics make that behavior interoperable; heuristics merely keep incomplete legacy fonts usable.

従来の一 em 正方形 CJK box は有用な既定値である。しかし、日本語フォントに普遍的な真実ではない。フォント作者は、非正方形および可変の box を含む別のデザインを表現できなければならず、フォントが意図的にアドバンスまたは字形インクだけを変化させる場合、エンジンは固定のデザイン box を維持しなければならない。明示的なメトリックによってこの挙動は相互運用可能になる。ヒューリスティックは、不完全なレガシーフォントを利用可能に保つだけである。
